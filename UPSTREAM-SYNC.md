# Upstream Sync — Curated Adoption

This is a **divergent personal fork** of [huytieu/COG-second-brain](https://github.com/huytieu/COG-second-brain). We do **not** `git merge` upstream. We review upstream releases and port the capabilities we want into our own architecture by hand.

## Why not merge

The fork and upstream have different architectures:

| | This fork | Upstream |
|---|---|---|
| Skill source | `.agents/skills/*/SKILL.md` (single source of truth) | `.claude/skills/` hand-edited, plus per-tool native dirs |
| Tool files | Generated by `cog-sync.sh` (`.claude/`, `CLAUDE.md`) | `.claude/agents/`, `.gemini/commands/`, `.cursor-plugin/`, `.claude/roles/` maintained separately |
| Context files | `AGENTS.md` source → `CLAUDE.md` header + append | Restructured CLAUDE.md/AGENTS.md that assume the per-tool layout |

A straight merge drags upstream's per-tool file layout on top of our single-source design, regressing it for no functional gain. The *value* in an upstream release is content and concepts, which port cleanly into `.agents/skills/`. The *conflict* is only the file layout.

## Remotes

- `public-souce` → `huytieu/COG-second-brain` — upstream framework (review only, never merge)
- `my-fork` → `gius/COG-second-brain` — this fork
- `origin` → `gius/my-second-brain` — the private vault

## Procedure

State lives in the vault: `04-projects/cog-customization/PROJECT-OVERVIEW.md` tracks the **last-reviewed upstream commit** and a decision log.

```bash
# 1. Fetch upstream (no merge)
git fetch public-souce

# 2. Review the delta since last review (get <last-reviewed> from PROJECT-OVERVIEW)
git log <last-reviewed>..public-souce/main --oneline
# Read the release notes / PRs behind each line. Skim diffs for capabilities, not file moves.

# 3. Per new capability, decide: PORT or SKIP.
#    PORT target is always our source of truth, never a copied file:
#      - a skill        -> .agents/skills/<name>/SKILL.md   (new dir or edit)
#      - framework docs -> AGENTS.md
#    NEVER adopt upstream's per-tool dirs (.claude/agents, .gemini, .cursor-plugin,
#    .claude/roles) — cog-sync.sh owns those surfaces.

# 4. Regenerate tool surfaces from source
./cog-sync.sh

# 5. Review + commit
git diff
```

## After a review pass

Update `PROJECT-OVERVIEW.md`:
- Set **last-reviewed upstream commit** to the current `public-souce/main` HEAD (even if nothing was ported — a reviewed-and-skipped release still advances the pointer).
- Add a one-line decision-log entry: which upstream version, what was ported, what was skipped and why.

## Family distribution is separate

Family installs pull from `my-fork` via `cog-update.bat` (double-click). That is downstream distribution of *this* fork and has nothing to do with upstream sync.
